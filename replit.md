# AdCampaign Pro - Self-Serve Ad Campaign Creation Tool

## Overview

AdCampaign Pro is a self-serve advertising campaign creation platform designed for small businesses. The application enables users with no advertising expertise to create, launch, and monitor professional ad campaigns through a guided wizard interface. The platform features a multi-step campaign creation workflow, real-time budget calculations, audience template selection, and a comprehensive dashboard for tracking campaign performance metrics.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture

**Framework & Routing**
- React 18 with TypeScript for type-safe component development
- Wouter for lightweight client-side routing
- Vite as the build tool and development server with HMR support

**UI Component System**
- Shadcn/ui component library following Material Design principles adapted for business SaaS
- Radix UI primitives for accessible, unstyled components
- Tailwind CSS for utility-first styling with custom design tokens
- Inter and Roboto font families for typography hierarchy

**State Management**
- TanStack Query (React Query) for server state management and caching
- Local component state with React hooks for form data and UI interactions
- Progressive form data accumulation through wizard steps

**Form Handling**
- React Hook Form with Zod schema validation
- Multi-step wizard pattern with data persistence across navigation
- Immediate validation feedback and error handling

### Backend Architecture

**Server Framework**
- Express.js with TypeScript for API routes
- HTTP server with middleware for JSON parsing and request logging
- Custom middleware for response time tracking and request logging

**API Design**
- RESTful endpoints for campaign CRUD operations
- Validation using Zod schemas shared between client and server
- Error handling with appropriate HTTP status codes
- Response format: JSON with structured error messages

**Data Layer**
- Drizzle ORM for type-safe database queries
- Schema-first approach with TypeScript inference
- Repository pattern through `DbStorage` abstraction for testability

### Data Storage

**Database**
- PostgreSQL via Neon serverless driver
- Single `campaigns` table containing:
  - Business information (name, website, category)
  - Campaign settings (goal, location, audience template)
  - Budget configuration (daily budget)
  - Performance metrics (spend, clicks, CTR)
  - Metadata (status, timestamps)

**Schema Strategy**
- UUID primary keys generated by database
- Decimal type for precise financial calculations (CTR)
- Timestamp tracking for creation dates
- Default values for status and metrics
- NOT NULL constraints for required business data

### Authentication & Authorization

Currently, the application does not implement user authentication. All campaigns are accessible to all users. This is a deliberate architectural decision for the MVP phase focused on the core campaign creation workflow.

**Future Considerations**
- Session-based authentication likely to be added
- User-campaign ownership relationships
- Role-based access control for business accounts

### Design System

**Material Design Adaptation**
- Progressive disclosure through stepped workflow (Business Info → Targeting → Budget)
- Immediate visual feedback for user actions
- Scannable information hierarchy with clear typography scale
- Touch-friendly controls with appropriate spacing

**Responsive Strategy**
- Mobile-first approach with Tailwind breakpoints (sm, md, lg, xl)
- Container width constraints: wizard (max-w-3xl), dashboard (max-w-7xl)
- Adaptive layouts that stack on mobile and expand on desktop

**Visual Feedback Patterns**
- Toast notifications for success/error states
- Loading states with spinners and skeleton screens
- Interactive hover states on cards and buttons
- Elevation system using shadow utilities

## External Dependencies

### Third-Party UI Libraries
- **Radix UI**: Complete set of accessible component primitives (dialogs, dropdowns, tooltips, etc.)
- **Lucide React**: Icon library for consistent iconography
- **Recharts**: Charting library for campaign performance visualization
- **Embla Carousel**: Carousel component for potential image galleries

### Validation & Utilities
- **Zod**: Runtime schema validation shared between client and server
- **Drizzle Zod**: Automatic schema generation from Drizzle ORM models
- **date-fns**: Date manipulation and formatting utilities
- **class-variance-authority**: Type-safe component variant management
- **clsx & tailwind-merge**: Conditional CSS class composition

### Database & ORM
- **@neondatabase/serverless**: Serverless PostgreSQL driver for Neon
- **Drizzle ORM**: Type-safe SQL query builder and migration tool
- **connect-pg-simple**: PostgreSQL session store (imported but not actively used)

### Development Tools
- **Vite**: Build tool with plugins for runtime error overlay and development features
- **@replit/vite-plugin-runtime-error-modal**: Enhanced error display in development
- **@replit/vite-plugin-cartographer**: Development tooling for Replit environment
- **esbuild**: Fast JavaScript bundler for server code compilation

### API Integration Points
- Currently, no external advertising platform APIs are integrated
- The application simulates campaign metrics with mock calculations
- Future integration points likely include: Google Ads API, Facebook Ads API, analytics platforms
